# Video support — a separate "Videos" tab

## Context

The app currently only discovers/organizes photos (`.jpg/.jpeg/.png/.tif/.tiff`, enforced by a strict allowlist in `supportedExtensions.ts`). The user wants video files supported too, but explicitly **not** folded into the existing photo Gallery/Dashboard/Tags/People/AI pipeline — instead a separate "Videos" tab for browsing and playing video files found in the same watched folders. Confirmed scope (via clarifying questions):

- **Thumbnails/probing**: bundle `ffmpeg-static` + `ffprobe-static` as new dependencies to extract a real poster frame and read duration/resolution/codec. No such dependency exists in the project today.
- **v1 feature set**: browse + play only. No tagging, no search, no AI (embeddings/duplicates/faces) for video. Keeps the DB/IPC/UI surface small and avoids touching the existing photo pipeline at all.

Verified against the real codebase (not just the exploration report) that the patterns below match: `database.ts`'s idempotent `CREATE TABLE IF NOT EXISTS` + `PRAGMA table_info` migration style, `thumbnailService.ts`/`photoIngest.ts`/`thumbProtocol.ts`'s key/generate/regenerate-on-miss shape, `App.tsx`'s tab wiring (lines 250, 254, 333, 344, 605, 768-788), the reducer's `PhotoLibraryState` shape, `protocolUrls.ts`, `useGalleryGridLayout.ts`'s `photoCount` option, and `settingsHandlers.ts`'s remove/rename-folder handlers.

## Key decisions

1. **Videos get their own SQLite table (`videos`), repository, IPC namespace, and renderer state slice — never merged into `photos`.** Every AI/duplicate/throwback service queries `photos` filtered by `thumbnailStatus='ready'`; keeping videos in a separate table means those services need **zero changes**. Matches this codebase's existing "distinct concern, distinct table" precedent (`people`/`photo_faces` vs `tags`).
2. **ffmpeg-static + ffprobe-static, invoked directly via `child_process.execFile` — no `fluent-ffmpeg`.** v1 only needs one `ffprobe -show_format -show_streams` call and one `ffmpeg -ss <t> -frames:v 1` call; a command-builder abstraction isn't earning its keep. Matches how `metadataService.ts`/`thumbnailService.ts` call `exiftool-vendored`/`sharp` directly today.
3. **Video discovery reuses the existing folder set** (`state.folders`, Add Folder, exclude-folder settings) via a generalized `scanDirectory(root, excludePatterns, extensions)` (new optional 3rd param, defaults to today's `SUPPORTED_EXTENSIONS` so every existing call site is unaffected) — but is **not** wired into the live chokidar watcher for v1. A video dropped in while the app is running appears on next rescan/folder-add/restart, not instantly. Documented as a known v1 limitation, upgradeable later without a redesign.
4. **Same `excludedFolders` set applies to videos**, via an `activeVideosByPath` derived map mirroring `activePhotosByPath`'s existing choke-point pattern.
5. **Video poster thumbnails get their own protocol (`photag-video-thumb://`) and cache dir (`userData/videoThumbnails/`)** rather than sharing `photag-thumb://` — the existing protocol's regenerate-on-miss handler looks video up in the `photos` table, which wouldn't work for a video row.
6. **Playback reuses the existing `photag-file://` protocol as-is** (`toFileProtocolUrl`, already handles any file path via `net.fetch`) — but requires an **`index.html` CSP fix**: there is currently no `media-src` directive, so `<video src="photag-file://...">` would be silently blocked by CSP (falls back to `default-src 'self'`, which excludes custom schemes). This is the single most likely "why won't it play" bug if missed.
7. **v1 extensions: `.mp4`, `.m4v`, `.mov`, `.webm`** — reliably playable in Chromium's native `<video>` with no added library. `.avi`/`.mkv`/`.wmv` are excluded from discovery for v1 (ffmpeg could thumbnail them, but Chromium often can't play the codecs inside those containers — "shown in the grid but won't play" is worse than not showing it yet). Trivial to widen later.
8. **`@gfazioli/mantine-video`'s `<Video>` component for playback**, not a bare `<video controls>` tag. It's an official Mantine extension (mantine.dev/x/extensions), MIT-licensed, built for exactly this project's React 19 + Mantine 9.x versions, and wraps the native `<video>` element under a `src` prop (so it works with `photag-file://` the same way a raw tag would, needs the same CSP fix). It gives a Mantine-themed control bar, keyboard shortcuts (space/K play, J/L seek, arrows for volume, F fullscreen, P picture-in-picture), and PiP support for free — a better fit than hand-building chrome, per the project's own convention to reach for a library before rolling custom UI.
9. **Packaging**: `ffmpeg-static`/`ffprobe-static` ship plain OS executables, not native `.node` addons, so they are **not** covered by electron-builder's automatic native-code unpacking (unlike `sharp`) — must be added explicitly to `asarUnpack` in `electron-builder.yml`, and their resolved path must be rewritten from `app.asar` to `app.asar.unpacked` at runtime (spawn/exec calls aren't asar-transparent the way `fs` reads are).

## New files

**Main process**

- `src/main/services/videoExtensions.ts` — `VIDEO_EXTENSIONS = new Set(['.mp4', '.m4v', '.mov', '.webm'])`, mirrors `supportedExtensions.ts`.
- `src/main/services/ffmpegPaths.ts` — `getFfmpegPath()`/`getFfprobePath()`, rewriting `app.asar` → `app.asar.unpacked` in production (dev mode uses the raw package path). Add an ambient `.d.ts` shim for `ffmpeg-static`/`ffprobe-static` if they lack types (needed for `typecheck:node`).
- `src/main/services/videoMetadataService.ts` — `probeVideo(filePath)` (runs ffprobe, parses JSON for duration/width/height/codec/creation_time) and `readVideoRecord(filePath)` (stat + probe → `VideoRecord`), mirrors `metadataService.ts`'s `readPhotoRecord`.
- `src/main/services/videoThumbnailService.ts` — `videoThumbnailKeyFor`, `videoThumbnailFilePath`, `generateVideoThumbnail` (seeks to `min(duration*0.1, 3)`s, extracts one frame via ffmpeg, scales to 640px), `deleteVideoThumbnail`, `deleteAllVideoThumbnails`. Mirrors `thumbnailService.ts` field-for-field; cache dir `userData/videoThumbnails/`.
- `src/main/services/videoIngest.ts` — `ingestVideoMetadata`/`ingestVideoThumbnail`/`ingestVideoFile`, mirrors `photoIngest.ts`'s split-concurrency shape (metadata and thumbnail steps under separate `p-limit` pools). Never throws on thumbnail failure — records `thumbnailStatus: 'error'` instead.
- `src/main/db/videoRepository.ts` — `findVideoByPath`, `upsertVideo`, `incrementVideoViewCount`, `findAllVideos`, `findVideoByThumbnailKey`, `updateVideoThumbnail`, `removeVideo`, `renameVideoPath`, `renameVideoPathPrefix`, `pruneMissingVideos`. Mirrors `photoRepository.ts` minus tag/embedding/face concerns.
- `src/main/ipc/videoHandlers.ts` — `registerVideoHandlers()`: `video:getAll` (DB read for instant paint), `video:scanAll` (returns `{scanId}` immediately, runs discovery+probe+thumbnail in background, emits `video:scanProgress`/`video:scanComplete`), `video:incrementView`.
- `src/main/protocols/videoThumbProtocol.ts` — `registerVideoThumbProtocolScheme`/`Handler`, direct mirror of `thumbProtocol.ts` including the regenerate-on-miss fallback (via `findVideoByThumbnailKey`).

**Renderer**

- `src/renderer/src/components/Videos/VideosView.tsx` — tab root: header (count, "Rescan videos" button + simple progress text — not a reuse of `ScanProgressBar.tsx`, which is tightly coupled to the photo scan's reducer fields), Mantine `EmptyState` when empty, renders `VideoGrid`.
- `src/renderer/src/components/Videos/VideoGrid.tsx` — virtualized grid via `react-window`'s `Grid` (already a dependency, used by `GalleryGrid.tsx`) + `useGalleryGridLayout`. Flat grid only — no folder-sectioning/multi-select/list-view toggle in v1.
- `src/renderer/src/components/Videos/VideoGridTile.tsx` — poster `<img>` (or placeholder icon if not ready), duration badge, filename, click → `openVideoTab`.
- `src/renderer/src/components/Videos/VideoPlayerTab.tsx` — `@gfazioli/mantine-video`'s `<Video src={toFileProtocolUrl(video.filePath)}>` filling the tab, a slim info bar (duration/resolution/size/date — falling back to `mtimeMs` labeled "Modified" when `creationTime` is absent), fires `incrementVideoView` once on mount.

## Test coverage

Follow the existing convention exactly: `src/main/services/*.ts` get `.test.ts` files, `src/main/db/*.ts`/`src/main/ipc/*.ts`/`src/main/protocols/*.ts` do **not** (verified — `photoRepository.ts`, `scanHandlers.ts`, `thumbProtocol.ts` have no dedicated tests today). So: new tests for `directoryScanner.test.ts` (extend for the new param), `ffmpegPaths.test.ts`, `videoMetadataService.test.ts`, `videoThumbnailService.test.ts`, `videoIngest.test.ts` (all mocking `child_process.execFile`, mirroring how `metadataService.test.ts`/`thumbnailService.test.ts` mock `exiftool-vendored`/`sharp`); extend `photoLibraryReducer.test.ts` and `PhotoLibraryContext.test.tsx`; new `VideoGridTile.test.tsx`, `VideoPlayerTab.test.tsx`, `VideosView.test.tsx` (lightweight, mirroring `DuplicatesView.test.tsx` rather than attempting full grid coverage — `GalleryGrid.tsx` itself has no dedicated test either). `VideoPlayerTab.test.tsx` may need to mock `@gfazioli/mantine-video`'s `<Video>` if jsdom can't exercise real `HTMLMediaElement` playback internals — same precedent as this session's `Tooltip`/`DonutChart`/`BarChart` mocks for components jsdom can't fully render.
